## 2. Findings

### P0
- **P0-1 Production OAuth/MCP path unverified after the apply.** Bridge 0001–0008 applied 2026-11-07 18:03 (run 42399341274), schema READY, but: 0 rows in every OAuth table, no `/oauth/authorize|token|register` request in Render logs, every `POST /mcp` = 401. The owner approval (#130 comment 6710960913) made post-apply verification of Render, OAuth, MCP `initialize`, `tools/list` and read-only calls a condition. None performed; the apply is not even recorded on #130. The MCP product has had no authenticated call since the DB was initialized. Status must be `RESTORED_NOT_VERIFIED`, not DONE/PRODUCTION_VERIFIED. (Classified P0 because it is the declared P0 production package and its own closure criterion is unmet; not a security hole.)

### P1
- **P1-1 Event loop blocked by synchronous DB I/O with 130 s default connect timeout.** `bridge/server.py` OAuthBearerMiddleware and `bridge/oauth.py` token/authorize handlers call psycopg synchronously inside async handlers; only readiness sets `connect_timeout`. A slow/blackholed Aiven freezes the single free instance (all MCP + `/healthz`) for up to 130 s per request. Combined with no Render health check, outage is invisible.
- **P1-2 Runtime TLS verify-full (D02) not proven in production.** Gate is opt-in (`FCB_DATABASE_TLS_VERIFY_FULL`, `PGSSLROOTCERT`). Aiven's URI default is `sslmode=require`. No #130 evidence that Render env has the flag or a CA secret file. #174 comment classifies WP-008 "PRODUCTION_CONFIGURATION_PENDING" — correct, but `wp005_ab_decision.md` "D02 enforced before apply" applies only to the workflow, not the runtime. Status UNKNOWN → treat as NOT DONE.
- **P1-3 Least-privilege roles absent; runtime almost certainly uses `avnadmin`.** Only `avnadmin` exists (PHASE0). "Runtime never runs DDL" holds by code only. Combined with ip_filter 0.0.0.0/0 and termination_protection false, a leaked runtime DSN = full admin over the DB that also hosts quota/audit state. D03 says "immediately after recovery" — 2 days later not started; no executable workflow for role creation/finalize exists.
- **P1-4 No tested recovery.** Backups exist but no restore drill, no logical dump, termination protection off. Data now includes quota counters (§2.4) — loss/rollback could reset API-FOOTBALL day budget counters (over-budget risk) and OAuth tokens.

### P2
- **P2-1 No connection pooling / no concurrency cap vs max_connections 15** (fresh TLS connection per DB op; to_thread pool up to 32; CI live workflows share the DB). Expect `too many connections` → 503/500 under modest load, and high latency per MCP call (token check = 1 TLS handshake per request).
- **P2-2 Non-atomic token issuance/rotation** (`oauth.py:_token_payload`, `rotate_refresh_token` then two inserts in separate transactions) and unhandled DB exceptions in `/oauth/token`/`authorize_post` → generic 500 (not fixed codes). WP-007 scope, NOT_STARTED.
- **P2-3 OAuth persistence has no real-PostgreSQL test.** Only DCR is exercised against PG (in the roles test via `fcb_app`); auth-code/access/refresh save/consume/rotate are never run against PostgreSQL; the only OAuth PG test in `tests/test_oauth_metadata.py` is permanently skipped in CI (needs `DATABASE_URL`). WP-009's "runtime compatibility" covers readiness, DCR and both coordinators but not OAuth tokens or `browser_session_leases` through `fcb_app`.
- **P2-4 Render free plan**: spin-down/cold-start vs MCP client timeouts, single instance, frequent restarts, `healthCheckPath` empty. Any upgrade is a cost → owner (D07).
- **P2-5 `/healthz` always `ok:true`** even with `schema_state` EMPTY/DB_UNAVAILABLE; no readiness gating (by design "report only", but no alerting consumes it).

### P3
- **P3-1** Runtime readiness does not verify column-level schema (no fingerprint at runtime); a manual column drift with unchanged `schema_migrations` reads READY.
- **P3-2** `app/db.py` verify-full check validates env `PGSSLROOTCERT` but ignores a DSN `sslrootcert=` (libpq precedence) — still verify-full, fail-closed at connect.
- **P3-3** `.env.example` documents `DATABASE_REQUIRED` ("Neon write failures are fatal") — not referenced anywhere in code; stale Neon reference.
- **P3-4** Production schema carries legacy/out-of-scope tables (0002 decision_requests, 0004 canonical entities, 0005 pilot sealing, 0006 evaluation protocols) — 33 tables vs 10 runtime-required + tracking. Relevant to WP-021 (destructive removal owner-gated).
- **P3-5** CI DB jobs run only on `pull_request`; nothing re-runs on `main` after squash merge.
- **P3-6** Reaper polls the DB every 60 s even with `BROWSER_TOOLS_ENABLED=false` (keeps a connection churn and log noise when DB is down).
